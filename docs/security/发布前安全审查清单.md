## 剩余风险（发布时需明示）

- **Lease 可自造**：客户端自供 lease，无权威签发/签名校验；安全边界靠 L0/L1 只读 + 敏感过滤 + workspace 容器 + 策略拒绝维持。
- **敏感名过滤不可穷尽**：名字级防线对内容型 secret 无效（如 `config.js` 内嵌密钥）；`docs_index` 只存 path+title，不受影响。
- **TOCTOU（symlink/文件交换）**：`stat` 与 `readFile` 之间可交换；本地同用户威胁模型下可接受，多租户场景需 `fstat` 复核。
- **workspace lock 非分布式锁**：cooperative；pid 复用 → 永久 busy（fail-closed）；进程崩溃后默认 60s 才可 reclaim。
- **git 边界可超出 workspace**：~~嵌套仓库场景~~（**已修复 2026-08**：git_read 要求 workspace 本身为仓库顶层，否则 fail-closed）。
- **发布无签名/无 provenance**：需发布侧 `npm publish --provenance`（OIDC/密钥）。
- **npm audit 本机不可用**：当前 npm mirror 的 audit endpoint 返回 `[NOT_IMPLEMENTED]`（registry 基础设施故障）；CI 走 GitHub registry 不受影响，但依赖漏洞结论需在可信 registry 下重跑确认。

## 复核修正记录

- 审查初稿曾报告"workspace-lock quarantine 误删竞态可致双持锁"。复核结论：quarantine 为 `workspace.lock.reclaim-<uuid>` 私有路径，仅 reclaim 方本人可写；`quarantinedOwner.token !== owner.token` 分支在正常并发下不可触发，且删除目标是本人 rename 的 quarantine 而非其他进程的锁目录；跨进程"释放时删除新持有者锁"的竞态被 `isStaleOwner` 的 pid 存活检查堵住。故该项降级为"通过"，仅保留重入语义文档化建议。
