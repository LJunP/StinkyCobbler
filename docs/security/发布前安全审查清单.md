# 发布前安全审查清单

> 本清单必须对每组最终候选 bytes 重新执行。公开 npm/GitHub 版本、tag/Release/资产与 Codex/ZCode 真实宿主状态必须实时核验；历史结果、本地绿测试或配置检测不能替代。本文不授权发布、不构成安全认证。

## 审查范围与方法

- 覆盖：MCP/Runtime 的 Lease 权威性，路径、symlink、readScope 和敏感文件边界，Git 只读边界，workspace lock，WriteIntent/Evidence/Ledger 一致性，编排产物与上下文边界，发布链（workflow/release-gate/SBOM/checksum/package-smoke）以及文档一致性。
- 方法：逐项比对当前源码、对应回归测试、[CHANGELOG](../../CHANGELOG.md) 与 [SECURITY](../../SECURITY.md)。本次文档同步不代替最终的全量测试、打包安装、真实宿主及正式发布验收。
- 结论分级：通过（当前源码已闭合）/ 边界（已如实限定，不是已实现的强隔离保证）/ 发布门禁（每个发布候选快照都必须重新验证）。

## 已关闭的审查项

1. **`git_read` revision/path/repository/进程边界**：已修复，并补充单文件、literal pathspec、敏感路径、历史 blob、restricted tag peel、环境/config 执行面禁用，以及 Git metadata/object symlink 与外部存储校验。
2. **敏感文件名覆盖不足**：已扩充并引入统一 workspace path policy。
3. **`WORKSPACE_CONFIG_INVALID` 可回显过长/控制字符**：已限长至 200 字符并清理控制字符。
4. **package-smoke 未拦截 `.env.local` / `.env.*`**：已修复。
5. **SBOM scoped purl 未编码、hash 格式及单向存在性校验不足**：已改为 scoped 名编码、CycloneDX 十六进制 SHA-512，并对 lockfile 做双向 multiset 对账，拒绝缺失、重复、额外组件和畸形 hash。
6. **workspace lock 并发重入、过期上下文与多 workspace 锁序**：第三版已用 token/generation/holder 所有权、frame 生命周期、稳定锁序和 holder drain 关闭；随后复核出的 owner 发布/自动回收竞态通过关闭全部自动回收而 fail-closed，现有 19 项 lock 回归通过；先前独立 500 轮压力用于重入/锁序/资源清理证据，不等同于跨进程分布式锁证明。
7. **MCP 信任调用方提交的完整 Lease**：已改为 Lease ID 引用 + 服务端持久化记录为唯一权威。
8. **SKILL/README 的 init 和历史文档链接口径**：已明示创建 `.stinky-cobbler/` 控制面，历史设计日志不再冒充当前权威规范。

## 仍需明示的边界

- **Cooperative Mode 不是强隔离**：未经 Stinky Cobbler 路由的宿主/Shell/Git/第三方 MCP 操作不受其控制。
- **Lease 是本地 bearer capability，不是签名身份凭据**：持久化记录对受控执行是权威，但不提供数字签名、真实行为人身份、可信时间或外部见证。
- **宿主流程确认不等于 capability Approval**：编排的领域、contract 与 run 预算确认仍由宿主/Skill 保证，未形成独立的人机交互证明；repository-write/L2 的可执行权限则必须另有精确 capability Approval，并持久化到 Lease authority 链。
- **精确 capability Approval 才是 write authority**：Skill 的“询问时长”和 Lease `issuedBy` 标签不是引擎证明；write/L2 依赖绑定 Task authority hash、scope、budget、policy、actors 与 nonce 的 Approval，并在使用时重验。
- **取消/超时不是硬中断**：Runtime 只对内置只读 adapter 做同进程协作式 AbortSignal/boundary fencing；不能据此宣称会终止 Codex/ZCode worker 或任意副作用。
- **审查身份与宿主隔离未证明**：`INDEPENDENT_REQUIRED` 会拒绝记录中的同源 review，`SELF_REVIEW_AUDITED` 允许但标记；两者都不证明现实身份、进程、文件系统或宿主会话隔离。
- **多文件控制面不是一个事务**：单个业务文件替换/删除可以原子执行，但 Evidence、Ledger 和状态随后落盘；中途崩溃可能需要诊断与人工恢复，不承诺多目标 all-or-nothing。
- **没有结构化长期记忆**：`summary/evidence` 编排产物在 `2.0.1` 中被拒绝；没有完整的摘要压缩、检索、冲突解决、过期/撤销和跨会话恢复机制。
- **敏感名防线不可穷尽**：它不能发现普通文件名中内嵌的 secret，也不取代库外的 secret scanning。
- **仍有本地 TOCTOU、mount、残留锁与非分布式锁边界**：当地同用户可在路径/Git metadata preflight 与文件操作之间交换对象；Unix bind mount 等也不是可移植路径检查能完整证明的边界。workspace lock 不是分布式锁，也不自动清理残留锁。引擎会 drain 未 await 的已进入子树并把其失败传播到外层，但调用方的常规 API 契约仍是正确 `await` 嵌套操作，不应把持锁任务当作 fire-and-forget。
- **完整性产物不是身份保证**：SBOM 是依赖清单，checksum 是内容一致性校验；二者都不自动提供签名、漏洞无缺陷保证或发布者身份证明。

## 复核修正记录

- 审查初稿一度把 quarantine 私有目标解释为足以保证安全；进一步构造 owner 发布中与自动回收交错后确认，旧 reclaim 路径仍可能删除新一代锁。2.0.1 因此移除全部自动 stale/ownerless/malformed lock 回收：任何现存锁均保持 BUSY，`staleMs` 仅兼容。并发重入、过期 frame、未 await 子树与多 workspace 锁序则继续由 token + generation + holder、frame 关闭拒绝、holder drain/失败递归和稳定锁序保护。
- 早期“调用方提交的 Lease 字段可直接成为执行权威”的风险口径已被当前实现取代：调用方伪造的 Lease 字段不再被信任，服务端持久化 Lease 是唯一执行权威；但“本地 bearer capability 无签名、可改写控制面的攻击者不在威胁模型内”仍必须保留。
- 旧口径“`WORKSPACE_CONFIG_INVALID` 未限长”、“package-smoke 不覆盖 `.env.local`”和“SBOM 只比数量”已被当前源码与回归测试取代，不再作为未修复风险列示。
