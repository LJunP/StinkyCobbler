# ADR-0002：从权限门禁转向 AI agent 工具箱包管理器

- 状态：Accepted（2026-10-20）
- 取代：README 2026-09-21 的"必要维护模式 · 新功能冻结"声明中关于"不再增加平台功能"的部分
- 保留：ADR-0001 关于 Cooperative Mode、非沙箱、非模型平台的边界

## 背景

2.0.1 把产品收缩为"Codex / ZCode 本地仓库的可验证权限与变更门禁"，随后于 2026-09-21 冻结功能。2026-10-20 的架构评审（[docs/架构评审与发展规划-2026-10-20.md](../架构评审与发展规划-2026-10-20.md)）确认了三件事：

1. 治理内核（约 12k 行）安全思想扎实，但其高保证写入链对真实用户不可达：精确 Approval 需要的 `subjectHash` 没有任何公开命令能算出，一次写入需要 26 条命令。
2. 代码结构已经积累了明显的债务（上帝文件、约 20 份复制的辅助函数、`config ↔ storage` 循环依赖、O(N²) 账本、约 25 个无人读取的配置键）。
3. 作者决定把产品方向转向"让用户把 skill、MCP server、指令/记忆文件、知识源、插件包按自己的习惯配置进 Codex、Claude Code、Cursor、ZCode 等 agent 工具"。

这个方向与"权限门禁"不是同一个产品。现有代码中与新方向直接相关、且质量过硬的部分约 2.5k 行：受管文件安装（sidecar hash、内容寻址备份、冲突不覆盖、可逆回滚）、分层配置加载、路径安全、hash 链账本。

## 决策

### 产品定义（3.x）

Stinky Cobbler 是 **AI agent 工具箱的包管理器**：用户用一份声明式 `toolkit.yaml` 描述想要的 skill、MCP server、指令/记忆文件、知识源和插件包；工具把它安全地（dry-run 预览 diff、hash 校验、冲突不覆盖、内容寻址备份、一键回滚、本地账本）渲染到各宿主自己的配置位置，并能 `doctor` 出每个宿主的真实状态与漂移。

差异化不在"同步配置"本身（市面已有同类），而在继承自 2.0.1 的事务性、可预览、可回滚、冲突保护与可审计。

### 仓库与包

- 同一仓库、同一 npm 包名 `stinky-cobbler`，主版本升到 3。
- 评审中列出的资产提取为新内核：`src/io/`（受管文件、有界读写、分层配置、密钥引用、账本）、`src/hosts/`（HostAdapter 及各宿主实现）、`src/core/`（toolkit 领域模型、纯函数计划器、渲染器）、`src/app/`（命令即用例、Presenter）。
- 2.x 治理内核（storage / runtime / policy / domain / mcp）整体搬入 `src/gate/`，保留 `gate` 命令组，标记 deprecated，**冻结**：只修会丢数据或误导用户的 P0 缺陷，不再扩展，不增加行数（CI 守卫）。4.0 再决定删除或拆独立包。
- 首批宿主：Codex、Claude Code、Cursor、ZCode。Gemini CLI 放 M3。

### 删除

"口径收缩、代码不收缩"是过去债务的根源。本 ADR 要求：任何能力被声明为不可用，其 schema、YAML、文档必须在同一变更中删除。M1-T7 删除评审中列出的 declared-only 配置（两份无 schema 的策略文件、`templates.yaml`、16 个占位插件、`profile.rules.*` 等约 25 个无人读的键、`test-run.ts` 死代码、无人用的类型）。

### 对 2.x 用户的承诺

- 2.x 的持久化记录在 3.x 中保持可读与可安全终止（延续兼容与迁移政策）。
- 2.x 分支只修 P0，直到 3.0 GA 后 6 个月。
- `entry install-host` 与受管文件 sidecar 格式保持字节级兼容，由 golden 测试锁定。

### 不做（3.x）

- 不做 OS 沙箱、模型调用、agent 调度（延续 ADR-0001）。
- 不自建向量库或 embedding；知识库 / RAG 是"可注册的 MCP server 类型 + 数据源配置管理"。
- 不做托管云服务、账号系统。
- 不在 `toolkit.yaml` 或任何渲染产物中写入明文密钥；只允许 `${env:NAME}` 这类引用。

## 后果

- README、支持矩阵、SKILL 模板的口径在 M0 改为"3.x 方向 + 2.x 维护承诺"。
- 新代码受 [架构规则](../架构评审与发展规划-2026-10-20.md#25-严格规定与规则防屎山宪法) 约束，并尽可能由 ESLint / dependency-cruiser / 配置存活性测试在 CI 强制。
- 被拒绝的备选：A）2.0.1 原样冻结另起新仓库（资产要复制、安全基因易丢失、品牌重新积累）；C）推倒重写并改名（丢掉 767 项测试积累的边界经验，独立开发者周期过长）。
