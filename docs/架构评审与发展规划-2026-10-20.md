# Stinky Cobbler 架构评审与发展规划（2026-10-20）

> 评审对象：仓库 `main` 分支 `e4dcdb9` + 工作区未提交修改（`src/storage/writes.ts`、`test/writes.test.ts`）。
> 评审方法：通读 README / docs / CHANGELOG / Archify 架构报告；五路并行只读代码审计（存储层、运行时与策略层、CLI·MCP·宿主接入、配置扩展层、测试·构建·CI），每一路的关键结论我都回到源码逐条复核过；本机实跑 `tsc`、全量测试、重新 build 后复跑集成测试；联网核查了"agent 工具配置"赛道的现状。
> 标记约定：**事实** = 本次对过仓库或命令；**推断** = 由代码结构/经验得出；**未知** = 没核到，需要验证。价值判断单独标 **判断**。

---

## 0. 先说结论（三分钟版）

1. **项目是什么（事实）**：一个 18.8k 行 TypeScript 的本地 CLI + MCP 控制面，给 Codex / ZCode 的仓库操作加"任务 → 批准 → 租约 → 单文件写入 → 账本"的门禁。2.0.1 已发布到 npm；2026-09-21 起 README 宣布**功能冻结、必要维护模式**，并写明"已退出作者的学习路线"。
2. **内核质量（事实 + 判断）**：安全思想扎实（写前 hash、PREPARED→COMMITTED 事务日志、fail-closed、hash 链账本、受管文件 sidecar + 内容寻址备份 + 可逆回滚），767 项测试全绿，六矩阵 CI。但结构已经是早期屎山：一个 2551 行的上帝文件、同一套辅助函数复制约 20 份、`config ↔ storage` 循环依赖靠 12 处动态 `import()` 硬撑、账本每次追加全量重读（O(N²)）、大约 25 个配置键和 16/20 个插件"声明了但代码从不读"。
3. **产品可用性（事实）**：一次受控写入要 **26 条命令 + 8 个手写 JSON**；精确 Approval 必需的 `subjectHash` **没有任何 CLI/MCP 命令能算出来**，只有测试通过深层 import 源码才算得出。这意味着 2.0.1 的"高保证写入链"在真实用户手里**走不通**。MCP 还把所有运行异常吞成一个 `INVOCATION_FAILED`。
4. **你的新方向与现状的关系（判断）**：你想做的"让用户随心所欲把 skill / MCP / RAG / 插件 / 记忆 / 知识库配置进自己的 agent 工具"，和现在的"权限门禁"**不是同一个产品**。现有代码里真正能复用到新方向的资产大约 **2.5k 行**（宿主接入 + 受管文件安装/回滚 + 分层配置加载 + 路径安全 + 可选的账本），其余约 **12k 行治理内核**与新方向无关。
5. **我的推荐（判断，见 §2.4 三档方案）**：走**中道**——不原地重构整个治理内核，而是把上述资产提取成新的 toolkit 内核，治理内核降级为可选模块并冻结；用严格的架构规则（§2.5）防止新内核重蹈覆辙。下一版本 **3.0.0-alpha** 的目标是：一份 `toolkit.yaml` → 安全、可预览、可回滚地渲染到 Codex / Claude Code / Cursor / ZCode 四个宿主的 skill、MCP 与记忆指令文件。详细任务拆解见 §3.4。
6. **必须先过的门（事实）**：README 的冻结声明与你现在的方向相反。这是你的决定权，但需要一份 ADR-0002 正式撤销冻结并重新定义范围，否则仓库对外口径自相矛盾。

## 1.4 缺陷清单（按严重度分级，全部带证据）

严重度定义：**P0** 正确性/安全性缺陷或崩溃后不可恢复；**P1** 让真实用户无法使用或被误导；**P2** 结构性技术债，会放大后续每一次改动的成本；**P3** 工程基础设施缺口。

## 2.2 项目逻辑：它想证明什么、实际证明了什么

**它想证明的链**（README）：

```text
持久化 Task → 精确 delegate-capability Approval → 受限 Lease → 单目标 WriteIntent + preimage
→ 可选 write-confirm Approval → apply 前重验 → 业务文件变更 → Evidence + ledger + APPLIED journal → 条件回滚
```

**实际状态（事实）**：引擎内每一环都有实现和回归测试；但链的入口（精确 Approval）对真实用户不可达（D-15），中段必须经宿主 Shell（D-19），MCP 出口把失败原因抹掉（D-01）。所以今天这条链**只在测试里完整走通过**。README 2026-09-19 的"发布后验证"也止步于 Task 与账本层，没走到 write。

**历史愿景 vs 实际交付**（来自四份历史设计文档）：

| 原计划 | 结果 |
|---|---|
| 用户唯一决策 = via，工具自动决定多 agent 与角色序列 | 删除：现在每次写入约 5 次显式批准 |
| 对话框点选确认 → 持久化 Approval → 自动继续 | 仅散文：引擎要手写精确 Approval JSON |
| L0 读 / L1 受控写 | 已交付（L1 收缩到单目标） |

| 12 角色 + 角色工具表 | 交付，包内固定，不可扩展 |
| Plan 模型 + 执行循环 / 2.0 orchestrator-worker / 专才路由 / 独立审查门 | 仅状态记录，宿主做实际工作 |

**我的解读（判断）**：这个项目经历了"多角色 AI 开发编排平台"（2.0，2026-08-11）→"可验证权限门禁"（2.0.1，2026-08-24）→"冻结"（2026-09-21）三次收缩。每次收缩都靠 README 把口径改窄，但代码没有同步删减，于是留下大量 declared-only 的壳。这正是"屎山"的典型成因：**承诺收缩，代码不收缩**。

## 2.3 是否需要重构：顶级架构师视角

### 判定

**需要，但不是"原地重构整个项目"。** 理由分三层：

1. **资产与负债分离得很清楚（事实）**。真正与你新方向相关、且质量过硬的代码约 2.5k 行：`entry/`（宿主接入 + 受管文件事务）、`config/tiered.ts + scaffold.ts`（分层配置 + 脚手架）、`security/workspace-path.ts` 读侧、`contracts/schema-registry.ts`、`storage/ledger.ts` 的 hash 链（可选）。约 12k 行治理内核（授权链、编排状态机、只读 Runtime、写入事务）对"配置 skill/MCP/记忆到宿主"这个目标没有贡献。
2. **治理内核的债务修复成本高、收益归属旧产品（推断）**。按 §1.4 的 P0/P2 清单，把存储层做成 DAG、去重、修 fsync/TOCTOU、换账本索引，保守估计是 4～6 人周（独立开发者，标记为推断）。修完后得到的是一个更健康的"权限门禁"，而不是你要的 toolkit。
3. **新方向有现成的市场形态可对标（事实，联网核查 2026-10-20）**：Anthropic 2025-12 发布 Agent Skills 开放规范（agentskills.io），SKILL.md 已被 30+ 工具支持（Codex CLI、Gemini CLI 原生，Cursor 从 2.4 起原生或经 `.cursor/rules/` 兼容，各来源说法不一）；AGENTS.md 是另一条被 20+ 工具支持的指令文件约定；已有 AgentX（统一 CLI 管多宿主 MCP + Skills）、skill-man（Go，发现 Cursor/Claude Code/Codex/Windsurf 配置）、Portkey Skills Registry（托管，sync 到 Claude Code/Cursor/Codex）、agent-config-sync（Claude Skill，MIT）；第三方目录称 skills.sh 截至 2026-06 收录 6.5 万 skill、7.8 千 MCP server（**未核实，来自自述数字**）。记忆/知识库侧，Cognee（图结构记忆 MCP）、projectmem（本地 MCP）等已存在但多为早期项目。**结论：赛道不空，"把配置同步到多个宿主"已经有人做；差异化只能来自现有代码独有的东西——事务性、可预览、可回滚、冲突保护、可审计的配置变更。**

### 推荐方向（判断）

> **产品定义 3.0**：Stinky Cobbler 是"AI agent 工具箱的包管理器"——用户用一份声明式 `toolkit.yaml` 描述自己想要的 skill、MCP server、记忆/指令文件、知识源和插件包；工具把它**安全地**（dry-run 预览 diff、hash 校验、冲突不覆盖、内容寻址备份、一键回滚、本地账本）渲染到 Codex / Claude Code / Cursor / ZCode / Gemini CLI 等宿主各自的配置位置，并能 `doctor` 出每个宿主当前真实状态与漂移。

类比：Homebrew/apt 之于软件包，Terraform 的 plan/apply 之于基础设施。市面同类是"同步脚本"，我们是"带事务与审计的包管理器"。这恰好继承了 2.0.1 的全部安全基因，而不需要它的授权链。

### 治理内核怎么办

三个选项，我推荐 B：

| 选项 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A 保守 | 2.0.1 原样冻结，新建一个独立仓库/包做 toolkit | 零历史包袱；冻结声明无需撤销 | 2.5k 行资产要复制一份，两边分叉；品牌/npm 名重新积累；安全基因容易在复制中丢失 |
| **B 中道（推荐）** | 同仓库、同包名：提取资产为新内核 `src/core/*`，v3 的 CLI 以 `toolkit` 为主命令组；治理内核整体移入 `src/gate/*`，保留 `gate` 命令组，**标记 deprecated 并冻结**（只修 P0，不再扩展）；4.0 决定删除或拆独立包 | 一次迁移、保留 npm 存量用户与 Release 历史、安全基因直接继承；旧用户有平滑退路 | 仓库体量暂时变大；要严守"gate 不再长"的纪律；需要 ADR-0002 撤销冻结并重新定义范围 |
| C 进取 | 推倒重写，连名字一起换 | 最干净 | 丢掉 767 项测试积累的边界经验；独立开发者重写周期长；与 A 相比没有额外收益 |

**为什么不是"原地把 12k 行内核重构到位再做新东西"**：这是独立开发者最容易陷入的坑——把 6 周花在改善一个你已经决定不再作为主线的东西上。先做能产生用户价值的 toolkit，治理内核的 P0 只修"会丢数据/会错导向"的那几条（D-01、D-02、D-03、D-09、D-10、D-20）。

## 2.4 目标架构（3.x）

```text
packages/ (暂不拆 monorepo，先用目录分层；依赖方向用 dependency-cruiser 在 CI 强制)

src/
├── core/                     # 新内核，纯领域，不依赖 node:fs 以外的 IO 抽象
│   ├── toolkit/              # Toolkit 领域模型：ToolkitSpec, SkillSpec, McpServerSpec, InstructionsSpec, KnowledgeSpec, BundleSpec
│   ├── plan/                 # 把 ToolkitSpec + 宿主现状 → Plan（一组 FileOp：create/replace/merge/remove）；纯函数，可快照测试
│   ├── render/               # 每种 artifact 在每种宿主的渲染器（SKILL.md、.cursor/rules、AGENTS.md、mcp json/toml）
│   └── diff/                 # 人类可读 diff 与 JSON diff
├── hosts/                    # Host Adapter：一个宿主一个文件 + 一个 conformance 测试
│   ├── host-adapter.ts       # interface HostAdapter { id; detect(); locate(artifactKind, scope); readMcp(); mergeMcp(); supports(artifactKind) }
│   ├── codex.ts | claude-code.ts | cursor.ts | zcode.ts | gemini-cli.ts
│   └── conformance/          # 每个 adapter 必须通过的同一套测试
├── io/                       # 唯一允许碰文件系统的层
│   ├── managed-file.ts       # 从 entry/install-host 提取：sidecar、内容寻址备份、CAS 写、conflict、rollback
│   ├── fs-boundary.ts        # 从 security/workspace-path 提取：路径规范化、符号链接复验、有界读、**新增有界写**
│   ├── tiered-config.ts      # 从 config/tiered 提取：builtin + user + project 三层，按文件声明合并策略
│   ├── secrets.ts            # ${env:NAME} / ${file:path} 引用解析；永不写入明文
│   └── ledger.ts             # 从 storage/ledger 提取 hash 链 + 索引（可选 feature）
├── app/                      # 用例编排（命令 = 用例）
│   ├── commands/<name>.ts    # 每个命令一个文件：{ spec, parse, run(ctx) }，与 commander 解耦
│   ├── context.ts            # 一次构造：schemas、adapters、config、presenter
│   └── presenter.ts          # human / json 双输出
├── cli.ts                    # 只做 commander 注册 + 错误→退出码
├── mcp-server.ts             # 可选：把 toolkit 查询暴露为 MCP（让 agent 自己查"我装了什么"）
└── gate/                     # 旧治理内核整体搬入（storage/runtime/policy/domain/mcp 原样），deprecated，冻结
```

**依赖方向（CI 强制）**：`cli → app → core | hosts | io`；`hosts → core | io`；`core` 不依赖 `hosts/io/app`；`gate` 只能被 `cli` 引用；禁止任何方向的循环；禁止动态 `import()` 用于绕过循环。

**深模块设计（用 codebase-design 词汇）**：

| 模块 | 接口（调用方必须知道的全部） | 深度体现 |
|---|---|---|
| `io/managed-file` | `install(target, bytes, {expectPrior?}) → Installed \| Conflict`、`rollback(target) → RolledBack \| Conflict`、`inspect(target) → State` | 背后：sidecar、hash、备份、CAS、symlink 拒绝、并发漂移检测。调用方不需要知道任何一项 |
| `core/plan` | `plan(spec, observations) → Plan`（纯函数） | 所有"该写什么、写哪、怎么合并"的决策都在里面；测试只喂数据不碰磁盘 |
| `hosts/HostAdapter` | 5 个方法 | 一个宿主的全部路径/格式/scope 知识；conformance 套件就是接口的测试面 |
| `io/tiered-config` | `load(kind) → {effective, layers, diagnostics}` | 合并策略、fail-closed、`fix` 提示 |

**seam 原则**："一个 adapter 是假 seam，两个才是真 seam。" HostAdapter 从第一天就有 4 个实现，是真 seam；runtime adapter 在旧内核里只有 1 个实现，这就是它为什么是假注册表。

## 2.5 严格规定与规则（防屎山宪法）

这些规则写进 `CONTRIBUTING.md` 并尽可能用工具强制。"尽可能自动化"是关键：靠自觉的规则在独立开发者项目里活不过两个月。

### A. 结构硬约束（CI 失败即阻断）

1. **文件 ≤ 400 行，硬上限 800**（ESLint `max-lines`）。`src/gate/**` 豁免但冻结（不许新增行数：CI 比对 gate 目录总行数不得增加）。
2. **函数 ≤ 50 行，嵌套 ≤ 4 层**（ESLint `max-lines-per-function`、`max-depth`）。
3. **依赖方向白名单**（dependency-cruiser）：违反 §2.4 方向、任何循环、任何用于解环的动态 `import()` 一律失败。
4. **单一事实来源表**：工具/宿主/artifact 种类的枚举只允许定义一次（`core/toolkit/kinds.ts`），其他地方从它派生类型与 zod/ajv schema；grep 守卫测试检查不得出现第二份字面量数组。
5. **没有读者的配置键不准存在**：每个 schema 的每个属性都必须在 `src/` 里有消费点；`test/config-liveness.test.ts` 自动比对 schema 属性 vs 源码引用，发现孤儿键即失败。这条直接杀死 D-29 这类假 affordance。
6. **错误码注册表**：所有错误码在 `core/errors/codes.ts` 一处声明，附退出码与用户可读 `fix`；禁止裸 `new Error(...)` 抛出（ESLint `no-restricted-syntax`）。
7. **每个命令**：`app/commands/<name>.ts` 一文件一命令；必须同时提供人类输出与 `--json`；非零退出码必须对应注册表里的错误码；`conflict` 类结果非零退出。
8. **每个 HostAdapter** 必须通过 `hosts/conformance/` 全套测试才能注册；宿主特定逻辑只能出现在它自己的文件里（grep 守卫：`hosts/` 之外不得出现 `"codex"`、`"cursor"` 等字面量）。
9. **IO 只在 `io/`**：`core/` 和 `app/` 禁止 import `node:fs`（ESLint `no-restricted-imports`）。
10. **写磁盘必须经 `managed-file` 或 `fs-boundary`**：禁止在 `io/` 之外直接 `writeFile / rename / mkdir`。

### B. 测试纪律

11. 集成测试前自动 build（vitest `globalSetup`），或当 `src/**` 比 `dist/` 新时直接失败。
12. 测试与 `scripts/` 纳入类型检查（`tsconfig.test.json`）。
13. 覆盖率地板：`core/` ≥ 90%，`io/` ≥ 85%，`hosts/` ≥ 85%（`@vitest/coverage-v8`），下降即失败。
14. 行为测试优先：禁止新增对文档措辞、YAML 字面量的 `toContain` 变更探测器；现有 44 处在 M1 替换成不变量断言。
15. 每个 bug 修复先有复现测试（commit 顺序：test → fix）。
16. `core/plan` 必须可以在无磁盘的情况下测试（纯函数 + 快照）。

### C. 流程纪律

17. **Conventional Commits**，一次提交一件事；`commit` 与 `push` 分开。
18. **PR ≤ 400 行净变更**（超过必须拆）；每个 PR 对应 PLAN.md 一个任务。
19. **ADR 门槛**：难逆转 + 未来会疑惑 + 存在真实取舍 三项同时满足才写 ADR；否则 PROGRESS.md 一行。
20. **文档与代码同步**：删一个能力必须同一 PR 删它的 schema、YAML、README 行；"口径收缩，代码不收缩"是本项目过去屎山的根源，明令禁止。
21. **发布门**：`npm test` + `test:package` + 真实宿主冒烟（至少 Codex 与 Claude Code 各一次，记录宿主版本与候选 hash）才能打 tag。
22. **依赖**：新增运行时依赖必须在 PR 里写用途、周下载量/维护状态、更轻替代方案；运行时依赖总数上限 10。
23. **密钥**：`toolkit.yaml` 与任何渲染产物禁止出现明文密钥；只允许 `${env:NAME}` 引用；`package-smoke` 的敏感内容扫描扩展到所有渲染输出。
24. **语言**：标识符、错误码、日志英文；面向用户的 `message/fix` 支持 zh/en 两套文案，由 Presenter 选择，不在存储/领域层拼中文。

### D. 工具链

25. ESLint（typescript-eslint + 上述规则）+ Prettier + `.editorconfig` + `.nvmrc`（22.12）+ husky/lint-staged（pre-commit：lint + typecheck；pre-push：unit tests）+ dependency-cruiser + Dependabot（周）。

## 3.1 北极星与成功标准

**北极星**：一个开发者在任意一台机器上，用一份 `toolkit.yaml` 在 5 分钟内把自己习惯的 skill、MCP server、指令/记忆文件、知识源装进 Codex、Claude Code、Cursor、ZCode，并且随时能看到每个宿主的真实状态、预览改动、一键回滚。

**成功标准（3.0 GA）**：
- 4 个宿主的 conformance 测试全绿；真实宿主冒烟各一次有记录。
- `toolkit plan` 在没有任何写入的情况下给出每个文件的 diff；`apply` 之后 `doctor` 零漂移；`rollback` 之后 byte-for-byte 回到之前。
- 对用户已手改过的受管文件，永远 `conflict` 而不覆盖（继承 2.0.1 保证）。
- 从 `npm i -g` 到第一次成功 `apply` 的命令数 ≤ 4。
- 不在 `toolkit.yaml` 或任何渲染产物中出现明文密钥。

**明确不做（3.x DONT）**：
- 不做 OS 沙箱、不做模型调用、不做 agent 调度（延续 2.0.1 边界）。
- 不自己实现向量数据库/embedding。知识库/RAG = 把现成的 RAG MCP server（或本地文档索引工具）**作为一种可注册的 MCP server 类型**接入，并管理它的数据源配置；不重复造轮子。
- 不做托管云服务、不做账号系统。
- 不在 3.x 扩展 `gate/`。

## 3.3 `toolkit.yaml` 模型（M2 的核心契约，先定下来）

```yaml
version: 1
hosts: [codex, claude-code, cursor, zcode]     # 渲染目标；省略 = 全部已检测到的宿主
scope: user                                      # user | project（project 写到当前仓库内的宿主目录）

skills:
  - id: code-review-checklist
    source: ./skills/code-review-checklist       # 本地目录，含 SKILL.md（Agent Skills 规范）
    hosts: [codex, claude-code]                  # 可选，覆盖顶层
  - id: lark-doc
    source: git+https://github.com/example/skills#lark-doc   # M3 才支持远程来源

mcpServers:
  - id: filesystem
    transport: stdio
    command: npx
    args: ["-y", "@modelcontextprotocol/server-filesystem", "~/projects"]
    env:
      API_TOKEN: ${env:FS_TOKEN}                 # 只允许引用，禁止明文
  - id: docs-rag
    transport: stdio
    command: cognee-mcp
    role: knowledge                              # M4：标记为知识源，doctor 会检查其数据源
    sources: [./docs, ~/notes]

instructions:                                    # "记忆"的最小形态：按宿主渲染的指令文件
  - id: my-style
    source: ./instructions/my-style.md
    render:
      codex: AGENTS.md                           # 追加受管段落，不整文件接管
      claude-code: CLAUDE.md
      cursor: .cursor/rules/my-style.mdc
      zcode: skill                               # 作为 skill 装入

bundles:                                         # M3：插件 = 命名的 skills/mcpServers/instructions 组合
  - id: fullstack-kit
    includes: [code-review-checklist, filesystem, my-style]
```

**设计决定（写进 ADR-0003）**：
- 分层：builtin 默认 → `~/.config/stinky-cobbler/toolkit.yaml`（user）→ `<repo>/.stinky-cobbler/toolkit.yaml`（project），复用 `tiered-config` 的 keyed-list 合并（按 `id` 替换或追加）。
- 受管段落：对 AGENTS.md / CLAUDE.md 这类用户会手写的文件，只接管 `<!-- stinky-cobbler:begin id -->…<!-- stinky-cobbler:end -->` 之间的段落，sidecar 记段落 hash；段落外内容永不触碰。
- 密钥：`${env:NAME}` 在 apply 时解析为宿主配置支持的形式（Claude Code `.mcp.json` 支持 `${VAR}` 展开则原样透传；不支持的宿主写入 `env` 字段但 **值仍是 `${VAR}` 占位 + doctor 提示**，绝不解析明文落盘）。这一条需要逐宿主核实（**未知**，M2 任务 T2.3 里有核查步骤）。
