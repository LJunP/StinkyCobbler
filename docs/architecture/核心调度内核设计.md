# 核心调度内核设计

## 核心定义

Stinky Cobbler 的内核是：

> **Evidence-Gated Capability DAG：证据门禁的能力约束任务图。**

它将 AI 协作从共享长对话中的自由发挥，变成：

```text
任务宪章约束
+ 最小上下文任务包
+ 短时能力授权
+ 独立角色复核
+ 可验证证据回执
+ 高影响行为人工审批
```

## 核心对象

```text
Task Charter
→ Task Capsule
→ Capability Lease
→ Isolated Agent
→ Evidence Receipt
→ Gate
→ Audit Event
```

| 对象 | 作用 |
|---|---|
| Task Charter | 明确目标、非目标、范围、风险、验收、停止条件 |
| Task Capsule | 仅传递当前角色所需的最小上下文 |
| Capability Lease | 为当前任务签发短时、范围受限能力 |
| Evidence Receipt | 返回事实、测试、风险、证据引用 |
| Gate | 阻止未设计写入、无证据完成或未审批外部动作 |
| Audit Event | 记录策略、工具、产物和审批事实 |

## 默认角色与显示名

内部 ID 是稳定协议；显示名可由用户修改。

| ID | 默认显示名 | 默认职责 |
|---|---|---|
| conductor | 总控 | 编排 DAG、发放 Gate、汇总，不写业务产物 |
| scout | 探路者 | 现状、前置条件、依赖和风险侦察 |
| planner | 规划师 | Charter、范围、非范围、验收、任务图 |
| architect | 架构师 | 状态机、模型、边界、ADR |
| builder | 构建者 | software-engineering Pack 中受限实现 |
| testwright | 测试师 | 软件测试、边界与故障实验 |
| sentinel | 哨卫 | 数据、权限、输入、Secret、外发边界 |
| reliability | 可靠性官 | 一致性、重试、缓存、队列、恢复性 |
| reviewer | 审阅者 | 独立质量审查，默认只读 |
| verifier | 验证员 | 验证产物、运行受限检查、收集证据 |
| operator | 运营官 | 已授权运行态审查或操作 |
| scribe | 记录员 | 归档回执、事实投影、审计证据 |

非代码 Pack 通常使用 `researcher`、`producer`、`policy-guardian` 等通用角色；`builder` 等是软件工程 Pack 的专用扩展。

## 最小 DAG 调度

不强制每次派发全部角色。总控依据任务类型、风险、写集、依赖和验证价值生成最小任务图。

```text
非平凡任务：
总控
→ 探路者（已有工作空间或复杂任务时）
→ 规划师
→ 架构师
→ Design Gate
→ 产出/构建角色
→ 按风险并行只读审查
→ 审阅者
→ 验证员
→ Evidence Gate
→ 必要时人工审批
→ 记录员
→ Done
```

### 路由规则

| 任务特征 | 最小角色组合 |
|---|---|
| 文档草稿 | planner → producer → reviewer → scribe |
| 研究报告 | planner → researcher → reviewer → verifier → scribe |
| 普通业务 API | planner → architect → builder → testwright → reviewer → verifier → scribe |
| 权限/上传/外发 | 普通链路 + sentinel |
| 事务/缓存/MQ/状态机 | 普通链路 + reliability |
| 数据分析 | planner → data-steward/producer → analysis-reviewer → verifier |
| Docker/K8s | 普通链路 + operator；外部变更需审批 |

### 并发规则

```text
同一 writeSet 的写入任务串行。
不同 writeSet 的写入任务可在隔离工作区并行。
只读审查、测试设计、风险分析可并行。
同一 Agent 不得既实现又审查同一 taskId。
```

## 任务状态机

```text
DRAFT
→ SCOPED
→ DESIGNED
→ APPROVED_FOR_EXECUTION
→ RUNNING
→ REVIEWING
→ VERIFYING
→ AWAITING_APPROVAL
→ ARCHIVED
→ DONE

任意状态可转：BLOCKED / REWORK / CANCELLED
```

## 七道门禁

1. **Charter Gate**：目标、非目标、范围、验收、风险、停止条件存在。
2. **Design Gate**：实现只能使用 FACT 与已批准 DECISION；PROPOSAL 不可直接实施。
3. **Write Gate**：写入者必须持有效 Capability Lease、隔离工作区和 writeSet。
4. **Independent Review Gate**：实现者不可审查同一任务。
5. **Evidence Gate**：必须提供相关验证证据，才可声明完成。
6. **Human Approval Gate**：L2/L3 高影响动作按策略要求人类批准。
7. **Archive Gate**：记录员归档脱敏回执并投影可供下一任务使用的 FACT/DECISION。

## 上下文隔离与事实治理

子 Agent 使用 fresh context，仅接收：

```text
Task Capsule
+ 相关事实 FACT
+ 已批准决策 DECISION
+ 所需的 Pack/Policy/Artifact 引用
+ 可调用能力和范围
+ 上游回执摘要
```

禁止传递完整主对话、其他 Agent 推理、无关产物、真实 Secret、未经脱敏的敏感输入。

| 类型 | 含义 | 能否作为实现前提 |
|---|---|---|
| FACT | 代码、测试、命令、审批、文档可验证事实 | 可以 |
| DECISION | 已批准的架构/业务决策 | 可以 |
| PROPOSAL | Agent 建议 | 不可以 |
| UNKNOWN | 未验证问题 | 不可以 |

## 完成条件

任务仅在以下条件均满足时进入 `DONE`：

```text
Charter 已完成
+ 设计已通过
+ 写入范围未越界
+ 独立审查已完成
+ 验证证据存在
+ 所有必要审批完成
+ 脱敏回执已归档
```
