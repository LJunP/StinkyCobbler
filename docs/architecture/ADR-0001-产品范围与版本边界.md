# ADR-0001：产品范围与版本边界

- 状态：Accepted
- 决策范围：当前主线及后续兼容版本

## 背景

Stinky Cobbler 同时包含 Task/Approval/Lease、受控仓库读写、Runtime、orchestration 状态和宿主安装材料。若把这些组件描述成“宿主 sandbox”“自动多 Agent 平台”或“自动安全保证”，会混淆引擎实际强制的边界、宿主需要自行完成的流程，以及尚未实现的能力。

发布状态也不能从源码版本、测试或历史记录推断。npm 版本、Git tag、GitHub Release、资产和真实宿主 E2E 是不同事实，且会随时间变化。

## 决策

### 产品定位

Stinky Cobbler 定位为 Cooperative Mode 下的**本地受控执行与审计层**。它只对经自身 CLI/MCP 路由的本地仓库操作提供：

- persisted Task 与 TaskAuthority；
- 精确 Approval 和 persisted Lease；
- scope/路径/sensitive-file 门禁；
- 单目标 WriteIntent、`expectedPreimageHash`、Evidence、ledger、条件回滚与恢复；
- 本地 contract/run/subtask/artifact/review/budget/cancellation 状态门禁。

### 明确非目标

本产品不宣称：

- 操作系统或宿主 sandbox、强制完全中介；
- 通用多 Agent 创建、监督、上下文隔离或 worktree/进程隔离平台；
- 自动安全、语义正确、真实身份、可信时间、不可篡改外部见证；
- 宿主、模型和插件完全本地/离线；
- CAS、结构化长期 Context/Memory 或跨会话检索治理；
- 自动发布、部署、消息、支付、签署或生产操作。

宿主原生文件工具、Shell、Git 写入与第三方 MCP 位于 Cooperative Mode 边界之外。需要强制中介的部署者必须另行提供只暴露受控工具的隔离环境，本项目不把该环境冒充自身能力。

npm 发布物只把 `stinky-cobbler` CLI 与 `stinky-cobbler-mcp` 声明为受支持执行面。`dist/**` storage 模块是内部实现而非 library API；package exports 只开放 `package.json` 元数据并阻断标准 deep import。若调用方能绕过两个 bin、直接加载安装路径或改写 workspace 控制面，它已经位于本项目的 Cooperative Mode 强制边界之外。

### 审查策略

`reviewPolicy` 在 Contract 创建时形成不可变快照：

- `individual` → `SELF_REVIEW_AUDITED`；允许同源 review，但保留非独立审计标记。
- `team`、`organization`、`regulated` → `INDEPENDENT_REQUIRED`；拒绝同源 review。
- 缺失配置或 legacy Contract → `INDEPENDENT_REQUIRED`，fail-closed。

这个策略只约束受控记录，不证明 reviewer 的现实身份或宿主隔离。

### 版本与发布事实

文档不得用“截至某日仍是某版本”作为长期当前状态。当前发布事实必须分别查询 npm、GitHub tags/Releases、资产/checksum/SBOM 和对应版本的宿主验证证据。

历史记录可以保留，但必须明确标为 dated historical snapshot，不能充当当前状态。源码版本、绿测试、package smoke 或 release gate 都不自动等于公开发布。

### 兼容与迁移

安全边界优先于旧记录继续执行。2.0.0 Lease/Contract/Plan 保持可读，并分别有公共 CLI `lease revoke`、`orchestration contract cancel`、`plan cancel` 安全终止路径。由于缺少当前 authority 快照，它们不可执行，必须重发 Lease、新建 Contract、重新生成/确认 Plan；不得手改旧记录绕过。

宿主升级只对 sidecar 当前 hash 或内置精确已知旧版 hash 匹配的受管文件自动进行。用户改动一律保护；备份按内容 hash 寻址；rollback 只在当前目标和备份均匹配记录 hash 时执行。业务写入回滚中断通过 `write rollback-recover` 在 journal/hash fence 下恢复。

## 后果

- 产品文案更窄，但可由源码与证据验证。
- 宿主集成、独立 reviewer 和隔离仍可作为部署方案，但必须标为 `HOST_PROCEDURAL`。
- 兼容迁移可能要求重建 authority 对象，而不是无提示续跑。
- 社区 Issue/PR 必须描述产品层级、迁移、安全边界和真实验证范围。
