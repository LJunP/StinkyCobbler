# 支持矩阵

本页描述当前代码与文档承诺的产品边界。已发布版本、tag、Release 资产和真实宿主验证状态会变化，必须分别查询 [npm](https://www.npmjs.com/package/stinky-cobbler)、[GitHub Releases](https://github.com/LJunP/StinkyCobbler/releases) 与对应版本的发布说明；源码版本号、配置检测或本地绿测试不能替代这些事实。

## 总体定位

Stinky Cobbler 是 Cooperative Mode 下的**本地受控执行与审计层**：它为经自身 CLI/MCP 路由的本地仓库操作提供 TaskAuthority、精确 Approval、持久化 Lease、单目标 WriteIntent、preimage、Evidence、回滚和 ledger 门禁。

它不是操作系统或宿主 sandbox，不是通用多 Agent 平台，也不自动保证安全、语义正确、审查者真实身份、审查独立、外部见证或完全离线。宿主原生文件工具、Shell、Git 写入和第三方 MCP 可以绕过本控制面。

## 平台与入口

| 项目 | 支持状态 | 边界 |
|---|---|---|
| Node.js | `package.json#engines` 当前要求 `>=22.0.0` | 以所安装版本的 manifest 为准 |
| ZCode | `install-host` 支持 command、Skill 与可选 MCP 配置 | 配置成功不等于重启后发现或消费者 E2E 通过 |
| Codex | `install-host --host codex` 支持 Skill 与可选 MCP 配置；无自定义 slash-command 文件 | 配置成功不等于真实宿主验证通过 |
| 其他宿主 | 未声明为受支持宿主 | 可自行接 CLI/MCP，但不能冒充官方宿主适配或验证 |
| CI 声明目标 | Ubuntu / macOS / Windows × Node 22 / 24 | 只是 workflow 目标；当前候选没有对应 commit 的成功 CI URL，结果为 `UNKNOWN/PENDING` |
| 其他操作系统 | 未声明为当前支持平台 | Node.js 可运行不能替代 symlink、mount、权限和 launcher 的真实平台证据 |

## 能力矩阵

| 能力 | 状态 | 说明 |
|---|---|---|
| TaskAuthority、精确 Approval、persisted Lease 重验 | `ENGINE_ENFORCED` | 对受控路径有效；本地 bearer/control-plane 记录不是签名身份 |
| 仓库读取、单目标 create/modify/delete | `ENGINE_ENFORCED` | 受 scope、敏感路径、WriteIntent、preimage 与 Lease 约束 |
| 条件回滚与 `write rollback-recover` | `ENGINE_ENFORCED` | 仅单目标、journal 完整且 hash 状态可判定；不提供跨 intent 事务 |
| `scripted-readonly` Runtime cancel/deadline | `ENGINE_ENFORCED` | 同进程协作式 `AbortSignal`/边界 fence；不是宿主 Agent 或进程硬中断 |
| orchestration contract/run/subtask/artifact/review 状态门禁 | `ENGINE_ENFORCED` | 不创建或监督真实 worker |
| Codex/ZCode worker、独立 reviewer、worktree/进程隔离 | `HOST_PROCEDURAL` | 必须由宿主另行提供和留证 |
| Profile 审查策略 | `ENGINE_ENFORCED` | Contract 创建时不可变快照：见下表 |
| Profile/Pack/Plugin 的外部系统能力声明 | `DECLARED_ONLY` | 受信任执行器存在并经当前宿主验证前不可宣称可执行 |
| CAS、结构化 Context/Memory、跨会话检索与冲突治理 | `NOT_AVAILABLE` | 文件 hash 不等于长期记忆系统 |
| 宿主/操作系统 sandbox、通用多 Agent 平台 | `NOT_AVAILABLE` | 不属于本产品范围 |

## 审查策略矩阵

`reviewPolicy` 在 Contract 创建时由 workspace Profile 解析并写入 Contract，之后不可随配置变化而改变。

| Contract 创建时的 Profile/配置状态 | 快照值 | 同一执行者提交 review |
|---|---|---|
| `individual` | `SELF_REVIEW_AUDITED` | 可记录，但必须保留 `sameSourceReview` / `SELF_REVIEW_NON_INDEPENDENT` 审计标记 |
| `team` | `INDEPENDENT_REQUIRED` | 引擎拒绝 |
| `organization` | `INDEPENDENT_REQUIRED` | 引擎拒绝 |
| `regulated` | `INDEPENDENT_REQUIRED` | 引擎拒绝 |
| 配置缺失或 legacy Contract 未携带字段 | `INDEPENDENT_REQUIRED` | fail-closed，按严格规则处理 |

上述规则只比较受控记录中的 executor/reviewer 标识，不证明现实身份、进程隔离或真实独立性。

## 持久化记录兼容

| 来自 2.0.0 的记录 | 可读 | 可安全终止 | 可继续执行 |
|---|---|---|---|
| Lease | 是 | 可 `revoke` | 否；返回 `LEASE_REISSUE_REQUIRED`，需按当前 authority/Approval 重发 |
| Contract | 是 | 公共 CLI `orchestration contract cancel` | 否；返回 `CONTRACT_REISSUE_REQUIRED`，需新建 Contract |
| Plan | 是 | 可 `cancel` | 否；返回 `PLAN_REISSUE_REQUIRED`，需重新生成/确认 Plan |

完整迁移、宿主 managed upgrade 和回滚规则见[兼容与迁移政策](./兼容与迁移政策.md)。
