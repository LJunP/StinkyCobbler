## 已实现与未实现

### 已实现的产品闭环

1. **配置与任务**：Profile/Pack、策略模板与校验、workspace 初始化、Task 生命周期及规则式角色推荐。
2. **授权与读取**：TaskAuthority、精确 Approval、持久化 Lease 重验、scope/writeSet/预算、文件与目录读取、固定 Git 只读命令、文档索引。
3. **受控变更**：单目标 create/modify/delete、WriteIntent、写前 hash、备份、Evidence、条件回滚与失败恢复；create/modify 的 auto-allow 仍执行其他门禁，delete 必须明确确认。
4. **计划与编排门禁**：Plan、Contract、Subtask、依赖、重试代次、冲突、产物 hash、审查规则、预算和完成条件。不负责真实 worker 创建。
5. **只读 Runtime**：受信任 `scripted-readonly` adapter、请求绑定、预算/心跳、协作式取消与超时、终态收据、事务 journal 和恢复核对。
6. **接入与审计**：CLI/MCP、Codex/ZCode 安装预览与受管升级/回滚、ledger hash-chain、Evidence/Receipt、打包 smoke、离线包与供应链校验脚本。

完整入口和保证矩阵见 [README](../README.md#当前实现能力矩阵)。具体参数和有序操作步骤见[使用说明书](quickstart/使用说明书.md)。

### 尚未开发，不应当作待修 bug

- 模型调用、自动创建/监督 worker、统一 Host Adapter。
- Provider 可验证 token receipt、CAS、ContextManifest、结构化长期记忆、跨会话检索与冲突治理。
- 非开发 Pack 对应的受信任外部执行器；通用 Shell、网络、部署及 Git 写工具。

这些能力应基于真实用户需求单独立项，不是 2.0.1 发布必须补齐的功能清单。

### 明确的设计限制，不用扩大范围“修复”

- Cooperative Mode 不能限制宿主绕过本工具；这不是 OS sandbox。
- 本地授权/审查标识不是签名身份，ledger 不是外部可信见证。
- 单目标写入不是多文件原子事务；崩溃可能需要显式恢复。
- cancel/deadline 是协作式停止边界，不能保证硬杀进程或停止在途调用。
- 状态层审查分离不证明真实人员/进程/模型的独立性。

## 剩余阶段与完成条件

1. **本地候选加固**：本轮修复、完整测试、审计、文档与包验证通过。
2. **远端源码候选**：最终提交取得六矩阵 CI，候选工作流产物全部绑定同一 SHA。
3. **真实宿主验收**：Codex/ZCode 分别完成安装、重启发现、受控操作与失败路径验证。
4. **正式发布**：单独授权后打 tag、发布 npm/GitHub Release；再对公开安装链验收。
5. **后续演化**：收集真实使用问题，再决定宿主适配或上下文等新能力；没有承诺日期或完成百分比。
