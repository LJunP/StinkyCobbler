# 分层配置指南（高级用户）

普通用户**零配置直接用**——所有默认值内置，不创建任何配置文件即可工作。
高级用户可以按需覆盖。本页说明所有可自定义项、放置位置与安全边界。

## 出场配置：模板开箱即用

`init` 初始化工作区时，工具**自动生成 4 个带中文注释的模板文件**到
`.stinky-cobbler/policies/`——每个键都标注了用途、默认值、改法与例子：

```
.stinky-cobbler/policies/
├── orchestration.yaml        # 预算/上限/Lease/审查阈值/敏感路径
├── specialists.yaml          # 专才自定义（含名称）
├── templates.yaml            # 话术/审查风格/语言
└── contract-templates.yaml   # 任务模板
```

**用法就是取消注释**：

```yaml
# defaults:   ← 取消注释此行，再取消注释下方要改的键
#   maxRounds: 5     ← 改成 →   maxRounds: 10
```

- 保存即生效，无需重启
- 未取消注释的键 = 内置默认值（随版本更新）
- 工具**绝不覆盖**你修改过的模板文件（重跑 scaffold 只会补生成缺失文件）
- 旧工作区补生成：`stinky-cobbler orchestration config scaffold --root <路径>`

### ⚠ 项目级配置（不是全局）

`.stinky-cobbler/policies/` 只对**当前项目**生效——换一个项目 = 另一套配置。
每个项目独立治理，没有全局配置层。

### ⚠ 生效范围与报错位置

- **生效范围**：保存后对**之后的新操作**生效（新建 run/契约/子任务/写入等）；
  正在进行的编排 run 使用创建时的预算，不会中途改变；审查阈值/振荡阈值类
  对之后的每一次审查即时生效。
- **报错位置**：改错（版本不符 / YAML 格式错误 / 违反收紧护栏）时，
  配置加载会 **fail-closed 直接报错**，绝不悄悄回退用旧值。报错出现在：
  - 直接终端使用：下一次编排命令的输出
  - AI 对话使用：AI 执行命令失败后转述给你（"失败（原因：配置无效…）"）
  - **主动验证（推荐，保存后跑一次）**：
    ```bash
    stinky-cobbler orchestration config show --root <路径>   # 加载失败即报错
    stinky-cobbler doctor --root <路径>                      # configCheck 显示配置健康
    ```
  若改错后什么都没触发，错误不会主动出现——所以**保存后先跑 config show 验证**是标准动作。

## 配置位置（两层）

| 层 | 位置 | 说明 |
|---|---|---|
| 内置默认 | 包内 `policies/*.yaml` | 随版本更新，**不要直接编辑**（会被覆盖） |
| 用户覆盖 | 项目 `.stinky-cobbler/policies/*.yaml` | 工作区级，优先于内置，可提交 git 审计 |

用户文件只需写**要改的键**（一层深合并）：未写的键自动使用内置默认值。
所有文件 `version: 1` 开头；版本不符或 YAML 语法错误 → 加载失败（fail-closed），不会静默回退。

## 可自定义项

### 1. 编排参数 — `orchestration.yaml`

```yaml
version: 1
defaults:
  maxRounds: 10            # 默认 5：全局轮次上限
  maxRetriesPerSubtask: 3  # 默认 2：单子任务重做上限
  maxSubtaskTokens: 400000 # 默认 200000：全局 token 预算
  costTokensPerSubtaskRound: 8000     # 成本估算参数
  orchestrateTokenThreshold: 50000    # 编排推荐阈值
  maxContractCriteria: 30   # 默认 20：契约验收标准上限
  maxSubtaskCriteria: 15    # 默认 10
  maxWriteContentBytes: 5242880       # 默认 1MiB：单次写入大小上限
  leaseDefaultMinutes: 120            # 默认 60：Lease 默认时长
  leaseMaxMinutes: 1440               # 上限
  leaseGraceMinutes: 15               # 到期宽限
  autoRejectScoreThreshold: 60        # 默认 0(关)：分数低于此值，ACCEPTED 自动变 REJECTED
  autoEscalateOnConsistencyFail: true # 默认 false：一致性检查失败自动升级
sensitiveExtraPaths:
  - internal/              # 追加敏感路径（只增不减）：写入/读取永远拒绝
```

**收紧护栏（不可放宽）**：
- `oscillationThreshold`（默认 2）：同缺陷指纹升级次数，**只可 ≤2**（设为 1 = 更严格；设为 3 加载即拒绝）
- 退化检测不可关闭

### 2. 专才注册表 — `specialists.yaml`

```yaml
version: 1
specialists:
  - domain: frontend        # 同名=覆盖内置（含自定义名称）
    title: 像素魔法师
    instructions: [遵循项目约定]
    acceptanceChecklist: [符合验收]
    negativeRules: [不越界]
    suggestedCapabilities: [repository-read]
  - domain: medical         # 新领域=追加
    title: 妙手仁心
    instructions: [以数据安全为先]
    acceptanceChecklist: [隐私零泄露]
    negativeRules: [不输出患者信息]
    suggestedCapabilities: [repository-read]
```

匹配：精确 → 前缀（`frontend/forms` → `frontend`）→ `general` 回退。**general 可改名但不可消失**。

### 3. 话术 / 审查风格模板 — `templates.yaml`

领域确认引导话术、审查评语风格（简洁/详细）、指令语言偏好（zh/en）。
通过 `orchestration config show` 查看；消费方为 orchestrator skill（高级用户可直接编辑宿主侧 skill 文件定制交互文案）。

### 4. 契约模板库 — `contract-templates.yaml`

```yaml
version: 1
templates:
  - name: custom-audit      # 同名=替换，新名=追加
    description: 自定义审计
    domain: compliance
    goal: 审计目标
    criteria: [c1]
    scope: [docs]
```

用法：`stinky-cobbler orchestration contract from-template custom-audit --task <id> --root <路径>`

### 5. 已可改（无需配置文件）

| 项 | 位置 |
|---|---|
| 角色显示名 | `workspace.json` → `roles: {"scout": {"displayName": "侦察兵"}}` |
| 弹框文案 / 统一输出格式 / 编排规则 | 宿主侧 skill 文件（`SKILL.md`），重装不覆盖异内容 |

## 只读查看生效值

```bash
stinky-cobbler orchestration config show --root <路径>   # 生效值 + 用户覆盖项
stinky-cobbler orchestration specialist list --root <路径>
stinky-cobbler orchestration template list --root <路径>
```

## 安全边界（任何用户都不能放宽）

- 内置敏感路径不可删除（只能追加 `sensitiveExtraPaths`）
- 删除（delete）永不 auto-allow；覆盖与泛化范围仍需确认
- L3 人工确认、审计不可关闭
- 收敛阈值（振荡/退化）只可收紧
- `general` 专才回退不可消失

## Skill 与 MCP 的扩展边界

- **Skill**：SKILL.md 本质是文件——文案、规则、输出格式全部可编辑；`install-host` 检测到异内容会拒绝覆盖（conflict），你的修改不会被重装冲掉。修改不影响引擎安全（安全规则在 CLI/引擎层强制执行）。
- **第三方 MCP 服务器**：宿主层面可自行添加（ZCode/Codex 的 MCP 配置支持多服务器），Stinky Cobbler 不阻止。**注意治理边界**：第三方 MCP 工具不在 Stinky Cobbler 控制面内——不受 lease/审计约束。只读类风险可控；写类工具会绕过审计，自行评估风险。
- **工具自身的 MCP 服务器**：内置 9 个工具固定，不开放自定义工具集。

## Ledger 归档（增长控制）

```bash
stinky-cobbler ledger archive --before-days 30 --root <路径>   # 归档 30 天前的条目
stinky-cobbler ledger verify --root <路径>                     # 跨归档校验（含归档段）
```

归档 = 最老连续前缀移入 `ledger-archives/ledger-archive-<时间戳>.jsonl`，主链重写并留下
`ledger-archived` 事件（记录归档段尾哈希）；`verify` 从归档链经衔接点校验到主链——归档不破坏审计可验证性。
