# 非开发用户使用模型

Stinky Cobbler 不要求用户懂 Git、终端、MCP 或代码。

用户可以直接发起自然语言任务，例如：

```text
/stinky-cobbler 帮我整理本周客户会议记录，并生成待办和一封客户确认邮件草稿。
```

`via` 决定本次使用方式：`via=skill` 只做对话内建议，`via=mcp` 明确使用安装者配置好的本地读取能力，`via=auto`（缺省）仅在需要读取本地文件或控制面状态时自动使用本地能力。若提示“MCP 未配置”，请联系安装者执行 `stinky-cobbler entry install-host --mcp`。

系统应：

```text
识别 Profile 和 Pack
→ 推荐但不替用户选择模式
→ 生成任务与产物类型
→ 先生成内部草稿
→ 让审阅角色检查事实/敏感信息
→ 在发送邮件前要求人类确认收件人、内容和去向
```

非开发任务的关键不是仓库权限，而是：

```text
谁的数据
→ 为何读取
→ 生成何种产物
→ 是否持久保存
→ 是否跨系统更新
→ 是否对外发送
```

因此所有非代码 Pack 仍使用 Task、Artifact、Policy、Capability Lease、Evidence Receipt 和 Approval Gate。
