# 非开发用户使用边界

当前主定位是：**Cooperative Mode 下 Codex / ZCode 本地仓库的受控执行与审计层**。

研究、邮件、CRM、内容生产、付款、签署、发布等非仓库场景在历史设计中有 Profile/Pack/Plugin 声明，但当前并没有经过验证的外部执行器、目的地控制或真实宿主 E2E。它们属于 **DECLARED_ONLY / NOT_AVAILABLE**，不能当作可执行产品能力。

## 当前可用范围

- 本地 workspace Task/Approval/Lease 控制面；
- 经受控 CLI/MCP 路由的仓库读、单目标写入/删除；
- 本地 Evidence/Receipt/ledger 记录；
- 内置 scripted-readonly Runtime；
- 本地 orchestration contract/run/subtask/review/artifact 状态门禁。

这些能力仍受 Cooperative Mode 限制，不能约束宿主原生工具。公开 npm/GitHub 版本与 Codex/ZCode 真实验证状态必须实时核验；源码版本、历史记录和配置检测都不能替代。

## 不应承诺的非开发能力

- 自动调用邮件、CRM、社交平台、支付、签署、生产或部署系统；
- 自动选择并启用 Plugin；
- 对外发送前的可靠身份/代表权验证；
- 全本地/离线模型处理；
- 自动多 Agent、独立审查或宿主级失败隔离；
- 结构化长期 Context/Memory。

Profile、Pack、Role 或 Plugin manifest 只能表示声明/推荐/配置候选；只有受信任实现实际存在、被当前配置选择、通过策略与 Lease admission，并在真实宿主中验证后，才能升级为可执行事实。

非开发用户若只需要治理本地仓库中的文档，可使用与代码相同的 TaskAuthority、精确 Approval、Lease、单目标 WriteIntent 和 preimage 门禁。任何外部动作都应停在建议或草稿，不得由本候选宣称已执行。
