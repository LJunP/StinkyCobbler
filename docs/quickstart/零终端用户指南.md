# 零终端用户指南

你不需要了解终端、Git 或 MCP。安装者完成 Stinky Cobbler 的本地安装，并执行一次显式宿主集成（`stinky-cobbler entry install-host`，需要 MCP 时加 `--mcp`）后，就可以在 AI 对话中输入：

```text
/stinky-cobbler 帮我完成一个学生管理系统的开发
```

也可以指定本次使用方式：

```text
/stinky-cobbler 帮我总结当前项目的 README via=mcp
/stinky-cobbler 解释什么是 Lease via=skill
```

- `via=skill`：只用对话内建议，不读取本地文件。
- `via=mcp`：明确使用本地读取能力（需要安装者已配置 MCP）。
- `via=auto`（缺省）：需要读取本地文件时才自动使用本地能力，否则仅做建议。

如果你看到了“MCP 未配置”的提示，说明安装者还没有执行 `stinky-cobbler entry install-host --mcp`。

## 你会看到什么

Stinky Cobbler 会把请求整理为任务草案，并给出 Profile、Pack 和模式候选。最适合的候选可以标记 **（推荐）**，但它会让你自己选择。

它不会直接创建业务项目、修改业务文件、提交代码、发消息、联网发布或部署系统。

## 初始化前后

当你明确选择 Profile、Pack、模式和项目位置后，AI 应先展示初始化预览。你确认后，才会在项目内创建隐藏的 `.stinky-cobbler` 控制面目录；其中的 `workspace.json` 是唯一支持的配置文件，不使用 `config.yaml`。

Pack 可能推荐一些 Plugin，但推荐不会自动启用。通常由安装者或管理员在 v2 配置中明确选择或禁用 Plugin；这个选择不会授予 Lease、审批或修改权限。旧版 v1 配置需要先预览 `config migrate --dry-run`，确认后再迁移；迁移只改控制面配置并保留备份，不改业务文件。

这个目录保存任务、回执、运行记录和审计信息，不包含你的业务代码。初始化也不会让 AI 自动获得修改代码的权限。

## 只读 Runtime 是什么

v0.3 可以运行一次受控的“只读查看”：一个 agent 在明确的任务、Capsule 和 L0 Lease 下，通过固定工具查看允许范围内的文件或目录。

它只能：

- 查看已允许的非敏感工作区文件或目录；
- 生成带 hash/locator 的证据引用、回执和运行记录。

它不能：

- 修改业务文件或任务状态；
- 运行测试、shell、Git 写入、网络、部署或生产操作；
- 读取 `.env`、密码、Token、私钥、受限资料或 `.stinky-cobbler` 元数据；
- 自动签发 Lease、自动批准或把任务标为 `DONE`。

如果请求取消一次只读查看，取消是协作式的：可能要等当前查看操作返回。看到 `CANCEL_REQUESTED` 不代表已经进入 `CANCELLED`，应再查看运行状态。

看到运行结果 `COMPLETED` 时，应理解为“这次只读查看已结束”，不是“项目已经完成”。

## 四类信息

- **FACT**：有命令、回执或其他明确来源支撑的事实。
- **DECISION**：你或负责人已经做出的决定。
- **PROPOSAL**：AI 的建议，还没有得到批准。
- **UNKNOWN**：还不清楚、需要补充证据的问题。

不要把建议、回执、测试输出、账本验证或只读 Run 状态，当作高风险操作的许可或任务完成证明。

## 审计记录的限制

本地账本的 hash-chain 可以发现当前记录链是否损坏，但不能证明没有人重写整个账本、事件一定发生过、操作者身份真实或内容已经获批。不要让多个进程同时向同一工作区写账本。
