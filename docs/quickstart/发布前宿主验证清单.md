# 发布前宿主验证清单

> 目的：在真实宿主（ZCode）环境中验证 `/stinky-cobbler` 统一入口可用。
> 执行者：**用户本人**。以下步骤会写入你的真实 `~/.zcode/`（命令文件、skill 文件与可选 MCP 注册），请逐条确认后执行。
> 每步含"预期结果"与"失败时排查"；完成后按实际结果反馈。
>
> 状态（2026-08-10）：**本机 CLI 侧验证已自动完成**——全局安装、命令文件、skill 文件、MCP 注册、preflight/ledger/plan/write 冒烟均通过。本文档剩余**步骤 3-6 必须在 ZCode 对话界面手动执行**（执行前先**重启/重载 ZCode**，使新命令、skill 与 MCP 注册生效）。

## 前置

```bash
npm install -g stinky-cobbler
stinky-cobbler --version     # 预期：1.0.0
stinky-cobbler doctor --json # 预期：healthy、repository-read executable
```

- 说明：本机已从本地 tarball 全局安装并验证（node v20.17 可运行，仅 EBADENGINE 警告——engines 声明的 >=22 为保守值）。

## 步骤 1：预览安装（不写盘）

```bash
stinky-cobbler entry install-host --dry-run --json
```

- 预期：`command.action === "preview"`（target 为 `~/.zcode/commands/stinky-cobbler.md`），`skill.action === "preview"`（target 为 `~/.zcode/skills/stinky-cobbler/SKILL.md`）。
- 排查：报 `ENTRY_TEMPLATE_MISSING` → 包内容损坏，重装。

## 步骤 2：安装命令文件与 skill（可选 `--mcp`）

```bash
stinky-cobbler entry install-host --json
# 需要本地 MCP 时：
stinky-cobbler entry install-host --mcp --dry-run --json   # 先看 diff
stinky-cobbler entry install-host --mcp --json             # 写入并备份
```

- 预期：`command.action === "installed"` 且 `skill.action === "installed"`（再次运行均为 `ready`）；`~/.zcode/skills/stinky-cobbler/SKILL.md` 内容与包内模板一致；`--mcp` 时注册写入 `~/.zcode/cli/config.json`（ZCode 用户级 MCP 官方位置，命令为绝对路径），原文件备份为 `config.json.bak-*`（原本无该文件则无备份，属正常）。
- 排查：`conflict` → 目标已有异内容，不覆盖（人工处理）。
- 注意：命令文件引用了 `skills: stinky-cobbler`，两者必须同时就位，`/stinky-cobbler` 才能完整工作。

## 步骤 3：Skill 模式（不调用 MCP，via 点选）

在 ZCode 对话输入（**不需要手动打 via，工具会弹框给你点选**）：

```text
/stinky-cobbler 解释什么是 Lease
```

- 预期：工具**先弹出三个通俗选项**（`纯 Skill` / `Skill + MCP` / `自动`，且必须有一个标注（推荐））→ 你**点击「纯 Skill」**（内部映射 `via=skill`）→ 纯 Skill 回答；输出含"结果 / 证据 / 边界 / 下一步"；未读取本地文件、未调用 MCP。弹框文案不得出现内部术语（Lease/workspace-id/preflight 等）。
- 排查：若没有弹出选项而是直接按 auto 执行 → skill 版本过旧，重新执行 install-host；若输出含内部错误码 → 会话未加载最新命令/SKILL，重新加载。

## 步骤 4：Auto 模式（读取本地，via 点选）

先在一个已初始化 workspace 的仓库（`stinky-cobbler init` 过）中：

```text
/stinky-cobbler 帮我检查当前项目的 README
```

- 预期：工具**弹出三个通俗选项** → 你**点击「自动」**（内部映射 `via=auto`）→ 工具经 MCP `repo_read` 读取 README（需要已签发的 lease，由 Skill 引导 `lease issue` 或使用已有）→ 统一输出。
- 排查：`MCP 未配置` → 步骤 2 未带 `--mcp` 或宿主未加载 MCP 注册；`LEASE_DENIED` → lease 未签发/过期。

## 步骤 5：受控写入（用户点选确认）

```text
/stinky-cobbler 修复 docs/README 的错别字 via=mcp
```

- 预期：先展示写入清单（文件+操作+用途）→ **常规 create/modify 自动放行**（不弹确认，审计 write-auto-allowed + 可回滚；宿主批准框若未开 auto-approve 仍由宿主弹出）；**删除/覆盖仍要求确认**；写入后 `write list`/`plan list` 可查、`write rollback` 可回滚。
- 排查：`WRITE_CONFIRMATION_REQUIRED` → 确认未完成；`WRITE_TARGET_FORBIDDEN` → 目标命中永远禁止清单。

## 步骤 6：安全断言

```text
/stinky-cobbler 删除 .env via=mcp
/stinky-cobbler 把这个项目的所有文件重写 via=mcp
```

- 预期：`.env` 被拒绝（永久禁止目标）；「全量重写」被**质疑范围**——工具先缩小为明确文件清单并让你确认，不会直接执行；任何未确认的写入都不发生。受控删除（`repo_delete`/`write delete`）：确认后执行删除（备份可回滚），删除永不自动放行。
- 排查：任何"直接执行"都说明 Skill 指令未生效，停止使用并反馈。

## 步骤 7：审计查看

```bash
stinky-cobbler plan list --root <workspace> --json
stinky-cobbler write list --root <workspace> --json
stinky-cobbler ledger verify --root <workspace> --json
```

- 预期：plan/write 可读、`ledger verify` valid。
- 排查：`LEDGER_INVALID` → 按诊断与显式恢复处理，不自动修复。
