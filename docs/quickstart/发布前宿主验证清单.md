# 发布前真实宿主验证清单

> 对每一组候选 bytes，本清单的初始状态都是 **UNKNOWN / PENDING**。历史版本、临时 HOME、CLI 单测或 MCP stdio 测试不能替代真实 Codex/ZCode 消费者验证。
>
> 公开版本、tag、Release 与资产必须实时查询 npm/GitHub。清单通过也不代表已发布，不代表所有产品缺口或安全风险已消除。

本清单会修改真实宿主配置。执行者必须先查看 dry-run 精确目标，并对 ZCode 与 Codex 分别授权。验证只覆盖 Cooperative Mode；不证明宿主其他工具被隔离。

## 0. 固定候选 bytes

```bash
node --version
npm install
npm run build
npm install -g .
stinky-cobbler --version
stinky-cobbler doctor --json
git rev-parse HEAD
git status --short
npm view stinky-cobbler version --registry=https://registry.npmjs.org
```

验收：

- Node.js >=22；
- CLI 返回与当前 `package.json` 一致的候选版本；
- 记录 exact commit 与完整 dirty 状态；dirty 工作区必须以候选快照/校验和固定，不能只写“当前代码”；
- 安装源和候选 bytes 已明确记录，不能把 registry 的另一版本当作当前 checkout。

## 1. ZCode 安装与重启发现

```bash
stinky-cobbler entry install-host --host zcode --mcp --dry-run --json
# 人工审查精确目标与备份计划后，才执行：
stinky-cobbler entry install-host --host zcode --mcp --json
```

随后完全重启/重载 ZCode。

验收：

- command/skill/MCP 配置位于当前实现声明的 ZCode 目标；
- 不覆盖异内容；修改既有配置前产生备份；
- ZCode 的实际 MCP 工具列表出现 Stinky Cobbler 工具；
- 从 ZCode 对话真正调用一个只读工具成功，而不只是 `preflight.mcpConfigured=true`。

未同时满足则 ZCode = `UNKNOWN/FAIL`。

## 2. Codex 安装与重启发现

```bash
stinky-cobbler entry install-host --host codex --mcp --dry-run --json
# 人工审查精确目标与备份计划后，才执行：
stinky-cobbler entry install-host --host codex --mcp --json
```

随后完全重启/重载 Codex。

验收：

- skill 与 `config.toml` MCP merge 目标正确；
- 原配置所有无关字段/servers 保留，异 command 冲突 fail-closed；
- Codex 实际发现 skill 与 MCP tools；
- 从 Codex 对话真正调用一个只读工具成功。

未同时满足则 Codex = `UNKNOWN/FAIL`。

## 3. 测试 workspace 与 TaskAuthority

在可丢弃的测试仓库初始化，不得使用生产仓库：

```bash
stinky-cobbler init \
  --workspace-id host-e2e \
  --profile team \
  --pack software-engineering \
  --mode reviewed-workflow \
  --root /absolute/path/to/test-repo
```

建立 scoped Task 和精确 capability Approval。Approval 必须绑定：

- `subjectKind=task-authority`、Task ID 与当前 authority hash；
- capability 与精确根 scope；
- policy version；
- requester、decider、nonce、expiry；
- maxToolCalls 与 budget expiry。

验收：

- 缺 Approval 的 repository-write/L2 被拒绝；
- scope 不精确、Task hash 漂移、Approval revoked/expired、budget 超限被拒绝；
- 父 Lease capability/scope/budget/session 扩权被拒绝；
- 未知 role、缺失 role→tools 映射、不允许的 concrete operation 与 capability/operation mismatch 被拒绝；
- `worker` 只能使用 orchestration-derived、subtask/attempt-bound Lease；
- 持久化 Lease 使用时重新 admission Task/Approval/parent/role/operation，而不是信任调用方 JSON。

## 4. 受控只读

从 ZCode 与 Codex 各自完成一次：

- exact Task/Lease 下读取允许文件；
- 读取 scope 外文件被拒绝；
- 读取 `.env`、控制面、symlink 逃逸目标被拒绝；
- Lease revoked/expired/call-limit 后被拒绝。

保存宿主可见输出、MCP 结果、Receipt/Evidence/ledger 引用。只记录“对话说成功”不合格。

## 5. 单目标 create/modify/delete 与 preimage

对每个宿主分别验证：

1. create intent 捕获 `expectedPreimageHash=null`；
2. modify/delete intent 捕获目标当前 bytes hash；
3. 精确 `write-confirm` Approval 一次性消费，并绑定 intent ID/version/hash、目标和 preimage；
4. 修改目标制造 preimage drift，apply 必须拒绝并要求新 intent/Approval；
5. create/modify `--auto-allow` 仍需要 TaskAuthority capability Approval、Lease/writeSet、intent hash、路径与 preimage；
6. delete auto-allow 必须拒绝；
7. 成功后 intent 才为 `APPLIED`。

随后验证条件回滚：

- create 仅在目标仍匹配 post-image 时删除；
- modify/delete 仅从独占私有备份恢复；
- 第三方改动、已有备份、linked/non-private 备份 fail-closed；
- 多个 intent 不得报告为原子事务。

## 6. Runtime cancel/deadline

只用内置 `scripted-readonly` adapter：

- 正常 repository-read/list 完成；
- 同进程 active Run 的 cancel 返回 `CANCEL_REQUESTED` 后最终 persisted Run 进入终态；
- deadline 产生 `RUNTIME_DEADLINE_EXCEEDED` / `TIMED_OUT` 语义；
- persisted terminal state 阻止旧 owner 覆盖；
- 在途调用竞争时 Receipt 报告底层结果 UNKNOWN；
- 每次成功 read 的 checkpoint 在 owner/epoch 失效时被拒绝；
- 分别注入 finalization `after-prepare` / `after-receipt` 中断，`runtime reconcile` 报告 `PREPARED`，`--repair` 幂等提交 exact Receipt/audit；
- finalization 缺失、损坏、Receipt/Run 冲突均 fail-closed，不能进入 Task `DONE`；
- `runtime recover` 只处理 stale `RUNNING`，不得代替 finalization repair。

验收报告必须写明：这是 `AbortSignal` + timer + boundary check 的协作式取消，不是 Codex/ZCode Agent、线程或进程硬中断。

## 7. Orchestration 边界

只验证本地状态门禁：

- contract/run/subtask/artifact/review/round/cancel 记录和绑定；
- `kind=file` 由引擎重读 bytes 并 hash；
- `kind=summary/evidence` 被拒绝；
- Contract 创建时快照不可变 `reviewPolicy`：`individual=SELF_REVIEW_AUDITED`；`team` / `organization` / `regulated` / 缺失配置=`INDEPENDENT_REQUIRED`；
- individual 同源 review 保留 `sameSourceReview` / `SELF_REVIEW_NON_INDEPENDENT`，严格策略下同源 review 被拒绝；
- cancel fence 撤销相关 Lease、拒绝未应用 intent、阻止后续 mutation；
- `subtask show` 读取的 `retriesUsed` 必须匹配 dispatch `--attempt`，dispatch 返回的 `activeAttempt` 必须贯穿 begin/artifact/review；旧 attempt 全部拒绝；
- ESCALATED Run 只接受当前 `resumeGeneration + 1`；旧人工 resume 决定不能重放到后续 escalation；
- exact create retry（含终态 Run）返回原 Run；新一代 Run 只能通过 `--supersedes-run <terminal-run-id>` 绑定唯一终态前驱。

取消不会撤销已落盘文件，也不会终止宿主 worker。

不要把以下内容计为通过项，除非宿主另有可核验证据：

- 自动创建多 Agent；
- fresh context；
- 独立 reviewer；
- host/process/filesystem failure isolation；
- 取消宿主 worker；
- 结构化 Context/Memory 或 CAS。

## 8. 退出与清理

- 查询所有测试 Run/worker 达到 completed/cancelled/error 终态；
- 撤销测试 Lease；
- 保留验收所需最小证据；
- 宿主配置回退必须使用安装时备份或受支持卸载/配置流程，不直接删除不明文件；
- 不删除用户其他 MCP、skill、任务或会话状态。

## 9. 结果格式

分别填写 ZCode 与 Codex：

```text
Candidate bytes:
Host/version:
Install/restart discovery: FACT PASS | FAIL | UNKNOWN
MCP consumer read: FACT PASS | FAIL | UNKNOWN
TaskAuthority/Approval: FACT PASS | FAIL | UNKNOWN
Write/preimage/rollback: FACT PASS | FAIL | UNKNOWN
Runtime cancel/deadline: FACT PASS | FAIL | UNKNOWN
Orchestration state gates: FACT PASS | FAIL | UNKNOWN
Host isolation/automatic agents/independent review: NOT PROVEN
Evidence paths + hashes:
Unresolved risks:
```

只有两宿主必需项都绑定到同一候选 bytes 并通过，才能把该候选的“真实宿主验证”从 PENDING 升级为 FACT。即便如此，commit、push、tag、GitHub Release 与 npm publish 仍需要单独授权和证据。
