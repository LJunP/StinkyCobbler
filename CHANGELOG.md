## 2.0

- Local orchestration state machine (`orchestration` CLI group): TaskContract anchor, subtask records, engine-reverified file-artifact hashes, per-subtask Lease bindings, review records, scope/budget/retry checks, and round consistency. The CLI does not create or supervise real workers; `failure isolation` here means persisted subtask/run state only, not host/process/filesystem isolation.
- Global constraint records: round/token budgets, defect-fingerprint oscillation, score regression, scope rejection, and ledger events. A host must call the transitions correctly; this is not an autonomous execution loop guarantee.
- Host workflow design: a ZCode/Codex main Agent may open workers that use governed tools. Historical experiments do not prove 2.0.1 host support, automatic worker creation, context isolation, or nested-Agent behavior; those claims remain pending real-host revalidation.
- Domain confirmation + specialist routing: contracts require a user-confirmed `domain` (`contract create --domain`); the specialist registry (`orchestration specialist list/show`) resolves exact → prefix → general fallback and engine-injects the domain's professional instructions, acceptance checklist and negative rules into every subtask package (`domainInstructions` — the only task instructions a worker sub-agent may follow); subtasks may narrow to a sub-domain (`subtask add --domain`).
- Tiered configuration (defaults for everyone, customization for advanced users): two-layer YAML loading (package-internal `policies/*.yaml` builtin + workspace overlay `.stinky-cobbler/policies/` that survives updates and wins on conflicts, one-level deep merge, fail-closed version/YAML validation). New `policies/orchestration.yaml` (budgets, cost model, limits, write size cap, lease defaults, auto-reject score threshold, auto-escalate on consistency fail, append-only `sensitiveExtraPaths`), `policies/specialists.yaml` (user specialists: same-domain replaces builtin incl. custom titles, new-domain appends, general fallback never disappears), `policies/templates.yaml` (confirmation/review-style/language dictionaries), `policies/contract-templates.yaml` (prebuilt goal/criteria/scope bundles + `contract from-template`). Convergence threshold (oscillation) is tighten-only (values > 2 rejected); built-in sensitive paths are never removable, only extendable. Read-only `orchestration config show` shows effective values vs user overrides.
- Verifiable ledger archiving: `ledger archive --before-days N` moves the oldest contiguous prefix into `ledger-archives/ledger-archive-<ts>.jsonl` (original lines intact), re-hashes the remaining main chain (first prevHash links to the archive tail), and records a `ledger-archived` event; `ledger verify` chains across archives (internal chain + cross-file links + main-chain anchor), so growth control never breaks audit verifiability.
- Post-initialization customization templates: `init` scaffolds four commented files under `.stinky-cobbler/policies/`; this does not make installation, host registration, workspace setup, Task/Approval/Lease issuance, or host verification zero-configuration.
